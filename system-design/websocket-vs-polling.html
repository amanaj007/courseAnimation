WebSocket vs HTTP Polling

Real-time communication · Short polling vs Long polling vs WebSocket vs SSE

Requests sent: 0
Messages received: 0
Overhead: High
Latency: ~500ms
Select a communication mode and click Start to see how messages are exchanged.

Short Polling

  • Client polls every N seconds
  • High overhead (many requests)
  • High latency
  • Simple to implement

Long Polling

  • Client holds connection open
  • Server responds when data ready
  • Lower latency than short poll
  • Better but still high overhead

WebSocket

  • Persistent bidirectional connection
  • Low latency, low overhead
  • Full duplex communication
  • Best for real-time apps

Server-Sent Events

  • Server → Client only (unidirectional)
  • Single HTTP connection
  • Auto-reconnect built-in
  • Good for live feeds/dashboards
