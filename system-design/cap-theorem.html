CAP Theorem

A distributed system can guarantee at most 2 of: Consistency · Availability · Partition Tolerance

Synced node Stale / unavailable Request packet Partition wall

CP System

Consistency + Partition Tolerance. On partition, refuses writes to stay consistent. May be unavailable.

e.g. HBase, Zookeeper, MongoDB

AP System

Availability + Partition Tolerance. Always responds but may return stale data during partition.

e.g. Cassandra, CouchDB, DynamoDB

CA System

Consistency + Availability. No partition tolerance — only works on a single node (not distributed).

e.g. Traditional RDBMS (single node)
